# Правила соревнования

1. Можно пользоваться любыми методами, главное — честно (**дополнять выборку нельзя**).
2. Скор считается честно, без «приколов».
3. Штрафа за корреляцию нет: используется матчинг на основе всех собранных решений, который определяет совпадение решения. Списанные друг у друга решения обнуляются. Генерация может выдавать схожие решения — с ней нужно быть аккуратнее.
4. Анализ данных в решении не обязателен (кроме претендующих на доп. баллы, см. ниже), но при желании можно добавить ноутбук с EDA в темплейт.
5. Решение — в виде ссылки на GitHub с заполненным темплейтом.
   Проверьте, что:
   - Docker собирается;
   - сохраняет файл с решением в правильном формате и в нужное место.
   По этому сохранённому решению будут сравниваться метрики с лидербордом.
   Сид зафиксирован: `993`. В моделях, если нужен сид, фиксируйте такой же.
6. Именование решения и Docker-образа — в соответствии с требованиями. Аналогично переименуйте себя на Kaggle — важно, чтобы не тратить время на сопоставление ников и фамилий.
7. Одинаковые скоры сортируются по времени сабмита (раньше — лучше).

## Оценка
- Пробитие **baseline 1** — начинают начисляться баллы (до этого бейзлайна баллы = 0).
- Пробитие **baseline 2** — даёт пробитие на 3 (55 баллов).
- Скоры до baseline 2 равномерно оцениваются в диапазоне **0–55**.
- Скоры выше baseline 2 делятся по квантилям 33,(3)% и распределяются в **удовл / хор / отл**.
- Внутри «уда», «хора» и «отла» оценки равномерно распределяются от нижней до верхней границы порогов.
**Доп. баллы:**
Топ‑10 мест (при условии, что они выше baseline 2) могут претендовать на дополнительные баллы (распределены равномерно по местам), если:
- подготовят презентацию с анализом данных и применённых методов;
- расскажут её на паре (строго не более 5 минут).
Все распределения оценок будут сформированы **только после удаления всех жуликов с лидерборда**.

## Описание задачи
В этом соревновании решается классическая задача **ранжирования товаров по поисковому запросу** в интернет-магазине.
На вход подаётся:
- текстовый поисковый запрос пользователя;
- набор кандидатов-товаров с их текстовым описанием;
- заранее размеченная релевантность каждого товара запросу по шкале 0–3.
Задача — для каждого запроса упорядочить товары так, чтобы наиболее релевантные поднимались наверх.
Качество решений оценивается метрикой **nDCG@10**.

## Метрика качества
Качество решений оценивается метрикой **nDCG@10** (Normalized Discounted Cumulative Gain на топ‑10 документов) по каждому запросу, с последующим усреднением по всем запросам.

### Подготовка данных
Используются два файла:
**solution.csv** — истинные метки релевантности:
- `id` — уникальный идентификатор строки;
- `query_id` — идентификатор запроса;
- `relevance` — целочисленная релевантность в диапазоне 0, 1, 2, 3.
**submission.csv** — файл участника:
- `id` — тот же идентификатор, что и в `test.csv`;
- `prediction` — вещественный скор релевантности (чем больше, тем лучше).
Для оценки метрики:
1. Объединяем `solution` и `submission` по колонке `id`.
2. Группируем строки по `query_id`.
3. Метрика считается отдельно для каждого `query_id`, итоговый скор — среднее значение по всем запросам.
Интерпретация `relevance`:
- `3` — высоко релевантный товар;
- `2` — релевантный;
- `1` — частично релевантный / слабо подходящий;
- `0` — нерелевантный.

## DCG@10 для одного запроса
Пусть для одного запроса есть несколько товаров с истинными релевантностями \(r_i\) и предсказанными скорами \(s_i\).
1. Сортируем товары по `prediction` по убыванию.
2. Берём первые \(k = 10\) объектов.
3. Считаем взвешенную сумму:
- на позиции \(i\) (начиная с 1) объект получает
  \(gain_i = 2^{relevance_i} - 1\);
- вклад позиции дисконтируется:
  \(discount_i = \frac{1}{\log_2(i + 1)}\).
Тогда:
\[
DCG@10 = \sum_{i=1}^{\min(10, n)} \frac{2^{relevance_i} - 1}{\log_2(i + 1)}
\]
где \(relevance_i\) — истинная релевантность объекта, стоящего на позиции \(i\) в порядке, заданном предсказаниями модели.

## IDCG@10 (идеальный DCG)
Чтобы нормировать метрику, строим идеальное ранжирование для того же запроса:
1. Сортируем объекты по истинной релевантности `relevance` по убыванию.
2. Берём первые \(k = 10\) объектов.
3. Считаем **IDCG@10** по той же формуле, что и DCG@10, но для идеального порядка:
\[
IDCG@10 = DCG@10 \text{ для списка, отсортированного по убыванию истинной релевантности}
\]

## nDCG@10 для одного запроса
Нормированная метрика для одного `query_id`:
\[
nDCG@10 =
\begin{cases}
\frac{DCG@10}{IDCG@10}, & \text{если } IDCG@10 > 0 \\
0, & \text{если } IDCG@10 = 0
\end{cases}
\]
Значение лежит в диапазоне \([0, 1]\):
- `1.0` — идеальное ранжирование;
- `0.0` — полностью плохое (или все релевантности нулевые).

## Evaluation
Файл предсказаний должен называться, например, `submission.csv` и иметь формат:
```text
id,prediction
0,0.123
1,5.678
2,-1.234
...
```

# Оформление соревнования


### 🎯 Шаблон проекта для соревнования
Это шаблон проекта для формирования решения соревнования.

#### 📋 Что нужно сделать

##### Шаг 1: Установка Docker
**Если у вас Windows:**
1. Скачайте Docker Desktop: https://www.docker.com/products/docker-desktop
2. Установите Docker Desktop
3. Запустите Docker Desktop (он должен быть запущен в фоне)
4. Проверьте установку: откройте PowerShell и введите:
   ```
   docker --version
   ```
   Вы должны увидеть версию Docker, например: Docker version 24.0.6

**Если у вас Mac:**
1. Скачайте Docker Desktop для Mac: https://www.docker.com/products/docker-desktop
2. Установите и запустите Docker Desktop
3. Проверьте установку в терминале:
   ```
   docker --version
   ```

**Если у вас Linux:**
1. Следуйте официальной инструкции: https://docs.docker.com/engine/install/
2. Проверьте установку:
   ```
   docker --version
   ```

##### Шаг 2: Скачивание и переименование проекта
1. Скачайте этот проект с GitHub
2. **ВАЖНО:** Переименуйте папку проекта на ваше `фамилия-имя` латиницей (например, `petrov-ivan`)
3. Откройте папку проекта в любом редакторе (VS Code, PyCharm и т.д.)

##### Шаг 3: Разработка решения
###### 3.1. Укажите ваши зависимости
Откройте файл `requirements.txt` и:
- Зафиксируйте нужные библиотеки с версиями (символ `#` в начале строки не нужен!)
- **ВАЖНО:** Указывайте точные версии пакетов (например, `scikit-learn==1.3.2`)
Пример `requirements.txt`:
```
pandas==2.1.3
numpy==1.26.2
scikit-learn==1.3.2
xgboost==2.0.2
```

###### 3.2. Напишите ваше решение
Откройте файл `main.py` и заполните его вашей загрузкой, предобработкой, процессингом и сохранением файла:
**⚠️ НЕ ЗАБУДЬТЕ ЗАПИСАТЬ функцию `create_submission()` - она создает ответ он должен быть в формате SAMPLE SUBMISSION!**
В корень проекта можно сохранять другие скрипты, на которые идёт ссылка вашего решения в `main.py`, а также ноутбуки с анализом данных.

##### Шаг 4: Тестирование решения локально (без Docker)
Перед сборкой Docker-образа убедитесь, что код работает:
```
# Создайте виртуальное окружение (опционально)
python -m venv venv
venv\Scripts\activate

# Установите зависимости
pip install -r requirements.txt

# Запустите решение
python main.py
```
После выполнения в папке `results/` должен появиться файл `submission.csv` с вашими предсказаниями.

##### Шаг 5: Сборка Docker-образа
Когда ваше решение готово и работает локально:
1. Откройте PowerShell (Windows) или терминал (Mac/Linux)
2. Перейдите в папку проекта:
   ```
   cd путь\к\папке\проекта
   ```
3. Соберите Docker-образ (замените `Petrov-Ivan` на вашу фамилию-имя):
   ```
   docker build -t petrov-ivan-solution .
   ```
Это займет несколько минут при первом запуске.
**Важные моменты:**
- В команде есть точка `.` в конце - не забудьте её!
- Имя образа (`petrov-ivan-solution`) должно быть маленькими буквами
- Используйте дефис `-` вместо пробела

##### Шаг 6: Проверка Docker-образа
Запустите ваш Docker-контейнер:
```
docker run --rm petrov-ivan-solution
```
Вы должны увидеть вывод вашей программы. Если есть ошибки - исправьте их и повторите сборку.

##### Шаг 7: Сохранение Docker-образа в файл
Когда все работает, сохраните образ в файл для отправки:
```
docker save -o petrov-ivan-solution.tar petrov-ivan-solution
```
Это создаст файл `petrov-ivan-solution.tar` в текущей папке.

##### Шаг 8: Отправка решения
Отправьте преподавателю ссылку на гитхаб репозиторий с загруженным проектом (проект должен называться в формате `petrov-ivan`)
